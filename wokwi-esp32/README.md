# Wayfinder: Wokwi transport test

This is a ready Wokwi project for the part we need to verify now: an ultrasonic scan travels as JSON over Wi-Fi into the local Wayfinder backend, then the existing browser console reads the same data.

## First launch

1. In VS Code install the **PlatformIO IDE** extension too. Wokwi runs compiled firmware; PlatformIO produces it.
2. Open the `wokwi-esp32` folder as the VS Code folder.
3. Wait for PlatformIO to finish its initial setup, then select the **Build** checkmark in the lower status bar.
4. Start `local_gateway_plain.py` from the repository root in a separate terminal: `python local_gateway_plain.py`.
5. In VS Code press `F1`, choose **Wokwi: Start Simulator**, and allow the Private IoT Gateway if it asks.
6. Serve the frontend from the repository root with `python -m http.server 5173 --directory prototype`, then open `http://localhost:5173/index.html`.

The Wokwi serial monitor will print `POST 200` for every transmitted sonar ray. The orange returns on the browser map are those HTTP requests, not generated by the browser.

## Changing the obstacle distance

While Wokwi is running, click the HC-SR04 sensor and adjust its virtual distance. The servo sweeps from 25° to 155°, and each reading goes to `/api/telemetry`.

## Hardware note

The ESP32 here is only the ready-made Wi-Fi transport stand. The final Uno R4 WiFi will send the same JSON using `WiFiS3`; the backend and frontend contract remain unchanged.
